# PM Atlas

**项目管理知识库与情景推演实验室**

[在线体验](https://pm-atlas-iman.ardent-pixie-5731.chatgpt.site) · [快速开始](#快速开始) · [项目架构](#项目架构) · [参与贡献](#参与贡献)

PM Atlas 是一个面向初级项目经理、项目管理学习者和案例设计者的交互式学习项目。它把结构化知识、完整项目主线和可持续推进的个人分支放在同一个产品里，让学习者先理解通用规律，再进入具体情景做判断，最后通过规则结算、文件差异和路径比较复盘结果。

> 核心学习路径：**理解知识 → 观察主线 → 接手情景 → 构建行动链 → 推进项目 → 比较与复盘。**

## 在线体验

- 主站：[pm-atlas-iman.ardent-pixie-5731.chatgpt.site](https://pm-atlas-iman.ardent-pixie-5731.chatgpt.site)
- 项目实验室：[车主远程控车应用项目](https://pm-atlas-iman.ardent-pixie-5731.chatgpt.site/#lab-schedule)

未登录用户可以浏览知识库、项目简介、32 周主线、关键指标、三个情景入口和部分项目文件。创建个人分支、查看受限文件、保存进度和使用 AI 复盘需要通过 ChatGPT 登录。

## 为什么做 PM Atlas

很多项目管理学习产品擅长解释概念，却缺少三个关键环节：

1. 知识如何落到一份具体项目文件或管理动作上；
2. 一个局部决策如何持续改变进度、成本、风险、质量和干系人状态；
3. 学习者自己的路径与理想主线究竟差在哪里。

PM Atlas 使用可版本化的案例数据、确定性规则引擎和 Git 式分支模型连接这三个环节。AI 只负责结构化复盘，不负责决定项目状态，也不能覆盖规则引擎的结算结果。

## 功能概览

### 项目管理知识库

- 5 个过程组、10 个管理领域和 49 个管理子过程；
- 32 份项目文件与 133 项工具和技术；
- 生命周期地图、文档触点地图和知识关系图谱；
- 管理过程、项目文件、工具与技术之间的可追溯关系；
- 可连续浏览的知识档案与案例补充说明。

### 项目实验室

- 沿 32 周时间轴浏览项目主线、里程碑、阶段门和关键指标；
- 在 W9、W17、W25 三个接手点创建相互独立的个人分支；
- 逐项查看邮件、报告、干系人消息和仪表盘异常；
- 从“项目文件、工具与技术、干系人”三个卡池构建行动链；
- 云端保存草稿，按周推进项目并获得可行动的缺口诊断；
- 根据业务状态生成文件级 JSON Patch 和逐字段差异；
- 查看主线与个人分支的 Git 式路径比较；
- 在情景结束后查看结局、规则复盘和 AI 结构化复盘；
- 通过“接手记录”切换和回看不同情景分支。

### 项目控制中心

项目页面联动展示 SPI、CPI、BAC、AC、里程碑、工作量、需求、风险、干系人、RACI、燃尽图、CCB、时标网络图和 WBS 等项目状态，并提供 32 份项目文件的目录、版本历史和分支差异视图。

### 隐私友好的站点统计

站点所有者可以在受保护的统计页查看登录用户、日活、分支创建、AI 复盘请求和情景材料首次查看等汇总指标。统计不保存原始 IP、页面输入或行动链具体内容。

## 首个案例

当前完整案例是“车主远程控车应用项目”：

| 项目属性 | 当前案例 |
|---|---|
| 周期 | 32 周 |
| 团队 | 约 8 人 |
| 预算 | BAC 260 万元 |
| 目标 | 交付车辆状态查看与远程控制相关能力 |
| 案例版本 | `car-control/v5`（新分支默认版本；v1–v4 历史分支仍可回放） |

三个核心情景：

| 周次 | 情景 | 训练目标 |
|---|---|---|
| W9 | 家庭成员共享需求进入项目 | 需求澄清、影响分析、变更控制、预期管理 |
| W17 | 供应商接口延期且核心工程师被抽调 | 关键路径、资源协调、分阶段交付、进度恢复 |
| W25 | 远程控制出现高危安全缺陷 | 质量门、范围裁剪、发布决策、干系人沟通 |

案例中的“主线”代表满足当前目标和约束的一条最短成功路径，并不意味着现实项目只有一个正确答案。

## 项目架构

```text
React / Next.js / Vinext
├── 项目管理知识库
├── 32 周项目控制中心
├── 情景行动链与分支界面
└── 管理员统计页
          │
Cloudflare Worker
├── ChatGPT 平台身份校验
├── 公开案例投影 API
├── 私有情景材料与规则引擎
├── 分支、回合、文件差异与复盘 API
└── 聚合统计 API
          │
Cloudflare D1
└── 用户映射、分支、草稿、快照、事件、文件差异与统计
          │
DeepSeek API（可选）
└── 情景结束后的结构化学习复盘
```

关键设计原则：

- **规则与展示隔离**：私有案例包只在 Worker 中加载，前端不能获得答案集合、判分规则、未来事件或终局条件。
- **确定性结算**：项目状态由规则引擎推进；AI 不修改项目状态，也不改变成功或失败结论。
- **可追溯分支**：接手、材料查看、回合提交、状态快照和文件变更均保留可追溯记录。
- **幂等写入**：创建分支和提交回合使用幂等键，防止网络重试造成重复推进。
- **案例不可变版本**：案例内容与用户运行数据分离，新案例版本不会改写历史分支。
- **最小化统计**：只采集实现产品分析所需的事件和日期，不保存原始 IP 或学习输入正文。

## 快速开始

### 环境要求

- Node.js `22.13.0` 或更高版本；
- npm；
- 如需完整的登录、D1 和发布能力，需要支持 Sites 的托管环境。

### 安装与运行

```bash
git clone https://github.com/Iman-GGG/PM-Atlas.git
cd PM-Atlas/prototype
npm ci
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。本地环境可以浏览公开内容；ChatGPT 平台身份、云端分支和托管数据库能力以部署环境为准。

### 常用命令

```bash
npm run build              # 构建生产版本
npm test                   # 构建并运行全部测试
npm run lint               # 运行 ESLint
npm run lab:validate       # 校验案例结构、引用和规则
npm run lab:package        # 生成私有案例包与公开投影
npm run lab:verify-public  # 检查公开构建是否泄露私有规则
npm run db:generate        # 根据 Drizzle schema 生成数据库迁移
```

## 运行时配置

运行时值应通过托管平台配置，不要写入仓库或 `.openai/hosting.json`。

| 配置 | 必需 | 用途 |
|---|---|---|
| D1 binding `DB` | 完整实验室必需 | 保存用户、分支、快照、事件、文件差异和统计数据 |
| `DEEPSEEK_API_KEY` | 可选 | 生成情景结束后的 AI 结构化复盘 |
| `ANALYTICS_ADMIN_EMAILS` | 可选 | 允许指定邮箱访问 `/stats`，多个邮箱用英文逗号分隔 |

未配置 DeepSeek 时，确定性规则结算、情景结局和规则复盘仍可正常工作，只有 AI 补充复盘不可用。

## 案例开发工作流

案例源数据位于 `content/lab-cases/<case-id>/<version>/`。修改案例后应执行：

```bash
cd prototype
npm run lab:validate
npm run lab:package
npm run lab:verify-public
npm test
```

`lab:package` 会生成两类产物：

- Worker 使用的私有案例包，包含完整规则和结算信息；
- 浏览器可以安全读取的公开投影，不包含答案、隐藏规则和未来事件。

请勿直接编辑 `prototype/worker/generated/` 或 `prototype/lib/lab/*.generated.ts` 中的生成文件。

## 仓库结构

| 路径 | 说明 |
|---|---|
| `prototype/` | Web 应用、Worker API、D1 schema、迁移、测试与 Sites 配置 |
| `content/lab-cases/` | 版本化项目案例、主线、文件、情景和状态基线 |
| `knowledge-base/` | 项目管理知识索引、工具与技术核查和关系数据 |
| `samples/` | 项目章程、风险登记册、干系人登记册等结构化样本 |
| `schemas/` | 案例与项目文件的 JSON Schema、评分和导出映射 |
| `scripts/` | 案例校验、打包、生成和公开投影安全检查 |
| `specs/` | 产品需求、技术方案和项目文件模板规范 |

## 测试与安全边界

测试覆盖：

- 登录状态、分支归属与越权访问保护；
- 案例公开读取和私有字段隔离；
- 分支幂等创建、草稿恢复和回合推进；
- 材料首次查看、行动卡解锁和行动链结算；
- 文件业务字段变化、历史快照和路径比较；
- D1 真实迁移、统计聚合和管理员权限；
- 公开投影不包含隐藏规则、答案字段或未来事件。

提交改动前至少运行：

```bash
cd prototype
npm test
npm run lint
```

安全问题请避免直接公开可利用细节；在仓库建立正式的 `SECURITY.md` 前，可以先通过仓库所有者的 GitHub 联系方式报告。
