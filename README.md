# PM Atlas｜项目管理知识库与项目实验室

PM Atlas 是一个面向初级项目经理和项目管理爱好者的渐进式学习产品。

产品围绕一句核心学习路径展开：

> **先看最优解，再做变式推理，最后与主线对比。**

用户先通过知识库理解通用规律，再在项目实验室中观察一个完整项目的最短成功路径；随后从关键节点接手项目，在真实材料、状态变化和管理约束下做出决策，最终比较自己的项目路径与理想主线。

## 产品结构

### 1. 知识库

知识库负责回答“项目管理通常应该怎么做”，以教材知识为基础建立可连续探索的结构化模型：

- 5 个过程组；
- 10 个管理领域；
- 49 个管理子过程；
- 32 份项目文件；
- 133 项工具与技术；
- 管理过程、项目文件、工具与技术之间的关系图谱；
- 可从生命周期地图、文档触点和全局图谱进入知识档案。

知识库强调完整呈现。实际项目可以按需要裁剪，但学习阶段应先看到完整的管理视野。

### 2. 项目实验室

项目实验室负责回答“面对一个具体项目时，我应该如何判断和行动”。它不是静态案例阅读器，而是一个基于真实项目状态的学习沙盘。

核心体验包括：

1. **观察主线**：沿 32 周时间轴查看项目最短成功路径、阶段门和里程碑。
2. **从这里接手**：在预设情景节点复制当周主线状态，创建个人项目分支。
3. **发现事件**：逐项打开供应商邮件、测试报告、干系人消息和仪表盘异常，而不是直接接收标准答案。
4. **构建行动链**：从项目文件、工具与技术、执行行动和干系人四类卡片中选择并连接必要管理动作。
5. **按周推进**：每次提交行动链后，项目推进一周并反馈客观状态变化与尚未闭环的缺口类别。
6. **路径复盘**：情景结束后叠加个人分支与理想主线，识别一致点、绕路、延期或失败节点。
7. **AI 评价**：确定性规则引擎负责项目结算，AI 只评价用户判断、证据、行动链和结果之间的一致性。

## 首个案例

MVP 使用“车主远程控车应用项目”作为首个完整案例：

- 核心团队约 8 人；
- 项目周期 32 周；
- 项目预算 BAC 260 万元；
- 目标是交付车辆状态查看与远程控制相关能力；
- 主线代表以最小必要管理动作实现成功的理想路径。

三个高价值接手情景：

| 周次 | 情景 | 主要训练目标 |
|---|---|---|
| W9 | 家庭成员共享需求进入项目 | 需求澄清、影响分析、变更控制与预期管理 |
| W17 | 供应商接口延期且工程师被抽调 | 关键路径、资源协调、分阶段交付与进度恢复 |
| W25 | 远程控制出现高危安全缺陷 | 质量门、范围裁剪、发布决策与干系人沟通 |

主线在安全发布情景中选择按期上线“只读/查看状态”能力，暂时关闭远程控制，优先保证质量并管理干系人预期。

## 技术架构

```text
Next.js / React / Vinext
        │
        ├── 知识库与项目实验室前端
        │
Cloudflare Worker
        ├── 登录身份校验
        ├── 案例公开投影 API
        ├── 私有情景材料与规则
        └── 分支和材料事件 API
        │
Cloudflare D1
        └── 用户映射、分支、回合快照与事件
```

关键原则：

- 私有案例包只在 Worker 服务端加载；
- 前端不能获得最小正确集合、判分规则、未来事件或终局条件；
- 项目状态由确定性规则引擎结算，AI 不修改项目状态；
- 分支写入采用幂等键，避免网络重试重复推进或重复扣减预算；
- 运行数据与案例数据分离，案例升级不能改写历史分支。

## 本地运行

需要 Node.js 22.13 或更高版本。

```bash
cd prototype
pnpm install
pnpm run dev
```

访问 `http://localhost:3000`。

常用命令：

```bash
pnpm run build                 # 构建网站
pnpm run test                  # 构建并运行全部测试
pnpm run lab:validate          # 校验项目实验室案例数据
pnpm run lab:package           # 生成服务端私有包与前端公开投影
pnpm run lab:verify-public     # 检查公开投影是否泄露私有规则
```
